# BARS Manager 3000 — 2.1.0

Лаунчер объединяет менеджер служб и **Bars Component Manager 3000**. Название модуля компонентов одинаково в заголовке, карточке и кнопке лаунчера, в окне «О программе». Кнопки запуска стали выше; увеличены отступы от правой и нижней границ карточек. Светлая и тёмная темы сохранены.

## Проверка и версии

Проверка работает без установщиков и не требует выбора каталога. При запуске ничего автоматически не устанавливается. Таблица показывает версию комплекта, подтверждённую версию в системе и короткую рекомендацию. Полные сведения доступны в подсказке ячейки и в текстовом отчёте.

| Ситуация | Предложение |
| --- | --- |
| Подходящей версии нет | Установить |
| Совместимая версия старее комплекта | Обновить |
| Версия совпадает | Действий не требуется; доступны переустановка и удаление |
| Совместимая версия новее комплекта | Пропустить; понижение заблокировано |
| Другое поколение или разрядность | Установить требуемое, найденное его не заменяет |
| Файлы и действующая регистрация не согласуются | Нужна проверка; автоматическая установка приостановлена |

Сначала показаны отсутствующие и устаревшие, затем требующие проверки, установленные и неподходящие для ОС. Внутри блоков компоненты сгруппированы по семействам. «Выбрать всё» отмечает все подходящие для этой ОС строки, включая предварительные версии; повторное нажатие «Снять выбор» снимает все отметки. Во время установки выбор блокируется. «Выбрать недостающие» выбирает отсутствующие и устаревшие рекомендованные компоненты. Предварительные .NET и неопределённые состояния автоматически не выбираются.

Для .NET Runtime и ASP.NET Core отдельно учитываются семейство, x86/x64 и ветка major.minor. Например, 8.0.32 удовлетворяет комплекту 8.0.31, а 9.0.x не заменяет требуемую 8.0.x. Это консервативное правило: пользовательские настройки roll-forward приложений не предполагаются. RC/Preview и стабильные версии, а также разные серии RC/Preview разделены. Полный номер сборки предварительной версии проверяется по метаданным DLL и действующей регистрации Windows, в том числе скрытой от списка «Установленные приложения». Остатки папки после удаления не считаются установленным runtime.

Для SQL/MSI учитывается действующий ProductCode и родственные продукты UpgradeCode, их версии и разрядность. DevExpress учитывается внутри своей ветки major.minor, Access — внутри поддерживаемого поколения. Developer Pack .NET Framework проверяется по нужному поколению SDK/targeting pack, их файлам и регистрации; более новый встроенный runtime сам по себе не заменяет targeting pack. Номер EXE Developer Pack не сравнивается с внутренним номером SDK как с одной версией. MSXML 6, предоставленный Windows, учитывается отдельно; штатные файлы ОС не предлагается удалять.

## Установка и управление

1. Нажми «Проверить систему», затем отметь нужные компоненты. Щелчок по строке выбирает её для отдельного действия; отметки в первом столбце формируют пакетный выбор.
2. Основная кнопка показывает доступное действие. В окне управления выбери «По рекомендации», «Переустановить» или «Удалить». Для более новой версии переустановка старым комплектом недоступна.
3. Каталог «Библиотеки» рядом с EXE определяется автоматически, независимо от пути. Если его нет, путь запрашивается только при установке/обновлении/переустановке. Для удаления каталог не нужен. Вложенные папки и имена файлов могут меняться: поддерживаемые пакеты определяются по метаданным EXE/MSI, а не по числовому префиксу имени.
4. Проверь очередь и подтверди UAC Windows. Зависимости SQL CLR/SMO и базовый runtime для ASP.NET добавляются автоматически. Сортировка таблицы не меняет порядок зависимостей.
5. Дождись завершения. После каждой операции выполняется новая проверка. При перезагрузке, ошибке или неподтверждённом результате очередь останавливается.

«По рекомендации» обновляет без предварительного удаления. Для малого обновления MSI с тем же ProductCode используются `REINSTALL=ALL REINSTALLMODE=vomus`. Переустановка явно удаляет выбранные зарегистрированные продукты выбранного поколения/разрядности, затем запускает комплект. Если подходящих версий несколько, удаление может затронуть несколько продуктов этой ветки; другие поколения и разрядности не включаются. Удаление запускает только зарегистрированные деинсталляторы. Отсутствие надёжного деинсталлятора останавливает действие; папки и DLL вручную не стираются.

«Отменить операцию» показывает предупреждение. После подтверждения новые пакеты не запускаются; текущему дереву процессов отправляется запрос закрытия окон. Через 2 секунды оставшиеся процессы этого задания принудительно завершаются. При закрытии активного модуля появляется такое же подтверждение: «Нет» оставляет окно и установку работающими, «Да» отменяет операцию и закрывает менеджер после очистки. Кнопка «В меню» после подтверждения отмены возвращает к лаунчеру; крестик завершает программу целиком. Чтение/проверка и копирование файлов также поддерживают отмену между блоками.

Отмена передаётся повышенному помощнику через защищённое событие, отдельно от занятого канала журнала. У каждого запуска — собственный Windows Job Object с контролем дочерних процессов и завершением при закрытии задания. В том числе обрабатывается завершение быстрого родительского EXE при продолжающейся работе дочернего процесса. Процессы выбираются по принадлежности этому заданию, а не по имени EXE. Общая системная служба Windows Installer и посторонние установки не завершаются.

Принудительное прерывание **не гарантирует откат**: сторонний пакет может оставить изменения, а серверная часть Windows Installer может продолжить завершение операции или откат вне дерева менеджера. После отмены дождись завершения системной операции и проверь компонент. Это ограничение показано в предупреждении и журнале. Успешный код внешнего установщика без подтверждения результата не считается доказанной установкой.

## Visual C++ и обязательный Lite

Самостоятельный **RuntimePack_Full_v21.7.30 исключён** из сканирования, каталога и установки, в том числе при загрузке старого сохранённого каталога. Программа не удаляет его файлы или уже установленные им компоненты.

Один EXE сборника Visual C++ представлен двумя независимыми профилями:

| Профиль | Установка | Проверка |
| --- | --- | --- |
| Старый + Lite | 2005/2008/2010/2012/2013 в тихом режиме; RuntimePack Lite | Требуемые 2012 (v11) и 2013 (v12), x86 и x64 на x64 Windows |
| Современный + Lite | Текущий v14 в тихом режиме; RuntimePack Lite | v14 (2015–2026), x86 и x64 на x64 Windows |

**RuntimePack Lite 20.3.3 всегда включён в команды обоих профилей; отключить его в менеджере нельзя.** Текущие задачи Inno прочитаны из самого EXE сборника: старый профиль `v0513,v0513\silent,rtl`, современный `v1522,v1522\silent,rtl`. Принудительная установка старого v14 и переход на сайт не выбираются. Если выбраны оба профиля, EXE вызывается для каждого; задача Lite входит в каждый вызов.

Проверка VC++ использует действующие регистрации официальных Redistributable и наличие DLL нужного поколения и разрядности. Название «Microsoft Visual C++ v14 Redistributable» поддерживается. Номера пакета VC2012 и его отдельных DLL относятся к разным версиям и напрямую не сравниваются. Состояние профиля показывает наличие проверяемых VC++, **не гарантирует полный состав Lite**: у него нет единого достоверного признака установки. При запуске профиля Lite включается независимо от этого состояния.

Перед запуском старого профиля дополнительно проверяется отсутствие более новых установленных VC++ 2005–2013, которые этот сборник мог бы понизить. В таком случае нужен обновлённый источник; принудительный откат не запускается.

## Каталог и журналы

В текущем комплекте 39 поддерживаемых файлов, которым соответствуют 40 строк: VC EXE имеет два профиля. Число строк не означает число независимых установочных файлов. Три ручные утилиты исключены: `Microsoft .NET Runtime 1.0.31.exe`, `Исправлятор .NET Famework.exe`, `Удалятор .NET Framework.exe`.

Каталог и выбранный путь сохраняются в `%LOCALAPPDATA%\BARS\Bars Service Manager 3000`. После изменения папки нажми «Проверить систему». Обычная замена версии поддерживаемого пакета не требует пересборки, но новый тип пакета, новая схема задач стороннего установщика или новое поколение Developer Pack могут потребовать доработки правил. Произвольные неизвестные установщики автоматически не запускаются. Для расширенной настройки поддерживается `libraries.catalog.xml` рядом с комплектом.

Отчёты очереди: `%LOCALAPPDATA%\BARS\Bars Service Manager 3000\LibraryReports`. Журналы установщиков: `%PROGRAMDATA%\BARS\Manager\LibraryLogs`. «Сохранить отчёт» включает версии, рекомендации и журнал. SHA-256 защищает от изменения файла между чтением каталога и установкой; это не проверка доверия к издателю.

## Запуск на чистой Windows

Основной EXE и встроенные помощники собраны против .NET Framework 4.6, уже присутствующего в базовой Windows 10. Совместимые более новые Framework подходят. Целевые ОС: Windows 10, Windows 11, Windows Server 2019 и новее с рабочим столом. Требования конкретных библиотек могут быть выше требований менеджера; например, Developer Pack 4.8.1 подходит не для всех старых ОС. Server Core и ARM64 не проверены.

Сборка 2.1.0 не подписана. Проверены логика, интерфейс обеих тем и обнаружение на текущем компьютере. Реальную установку/обновление/удаление внешних библиотек этой сборкой ещё нужно проверить на тестовой виртуальной машине; полной матрицы чистых ОС нет.
