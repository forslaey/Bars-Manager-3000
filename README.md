# Bars Service Manager 3000 — Менеджер служб BARS

Переносимая утилита для регистрации и управления вашими службами Windows.
Обычные службы используют ключи .exe: **`-i` для установки, `-u` для удаления**. Для HttpService предусмотрен отдельный режим .NET с выбранной учётной записью.

## Оформление 1.7.0

В светлой и тёмной темах используются фирменные зелёные акценты, кнопки с плавным осветлением при наведении и затемнением при нажатии, тумблеры с движущимся бегунком и круглые отметки выбора дат. Выбор нескольких дат остаётся независимым. Тумблер сохранения пароля сохраняет прежнюю защиту DPAPI. Реакция на нажатие работает и с клавиатуры; анимации учитывают системную настройку анимации меню. Нативные поля ввода сохраняют выделение, копирование и маскирование пароля, а обводка использует цвета темы.

## Быстрый запуск

1. Скопируй единственный `Bars Manager 3000 2.3.13.exe` в любую папку и запусти обычным двойным щелчком. При запуске программа сама найдёт зарегистрированные службы с системными именами `DK.*` и `Bars.*` (без учёта регистра).
2. Перетащи .exe службы BARS в окно или нажми **«Выбрать службу...»**.
3. Дождись проверки регистрации. Найденные службы появятся в общем списке **«Службы BARS»**.
4. Нажми **«Установить службу»** или **«Удалить регистрацию»**.
5. Подтверди запрос Windows на права администратора, если он появится. Утилита дождётся завершения .exe службы BARS и повторно проверит регистрацию службы.

Ярлыки создавать и редактировать не требуется. Само перетаскивание ничего не устанавливает и не удаляет.
Можно также перетащить .exe службы BARS на значок `Bars Manager 3000 2.3.13.exe` в Проводнике.

## Общий каталог служб

Выбор нового .exe не очищает таблицу. Программа запоминает .exe, для которых обнаружена зарегистрированная служба BARS, включая подтверждённую установку через эту утилиту. При следующем запуске список загружается автоматически и сверяется с диспетчером служб Windows.

В таблице собраны все зарегистрированные службы из запомненных .exe. Выдели нужную строку, чтобы запускать, останавливать и настраивать её. При выборе строки верхнее поле переключается на соответствующий .exe — процедуры установки и удаления относятся к нему.

Удаление одной службы не убирает остальные. Если .exe больше не зарегистрирован, его путь остаётся в каталоге для будущей проверки, а подтверждённо удалённые службы исчезают из таблицы.

Каталог хранится для текущей учётной записи в `%LOCALAPPDATA%\BARS\Bars Service Manager 3000\services.xml`. Если сохранить файл не удалось, новые .exe остаются доступны в текущем сеансе; предупреждение появится в журнале. Повреждённый исходный каталог не перезаписывается.

Службы с системными именами, начинающимися на `DK.` или `Bars.`, показываются сразу при первом запуске и при обновлении, даже без сохранённого каталога. Имя для отображения не используется для этого отбора. Остальные службы, включая `HttpService`, можно добавить выбором их .exe. Если путь автоматически найденной службы недоступен, управление по системному имени остаётся доступным при проверенном состоянии; сбор логов и процедуры установки/удаления для неизвестного .exe недоступны.

Если чтение служб временно не удалось, ранее показанные строки сохраняются как последнее известное состояние; действия недоступны до успешного обновления.

## Один файл и временные установщики

Установщики извлекаются только при процедуре .NET в отдельную папку сеанса `%TEMP%\Bars Service Manager 3000\session-<идентификатор>`. Их целостность проверяется по встроенным ресурсам, файлы защищены от изменения во время использования. Они не содержат пароль: учётные данные передаются через ограниченный локальный канал.

При закрытии во время работы со службой программа показывает короткое предупреждение и предлагает остаться или закрыть окно. При раннем закрытии результат установки, удаления или другого действия нужно проверить в оснастке «Службы» Windows. Работающий процесс службы не завершается принудительно. Временный установщик удерживает свой сеанс, а скрытый процесс очистки удаляет его файлы после завершения; при обычном выходе без активной процедуры они удаляются сразу. Сбор логов отменяется перед выходом. Остатки после аварии очищаются при следующем запуске; активные сеансы и неизвестные файлы не удаляются. Настройки сохраняются отдельно.

При первом запуске версии 1.6 прежние `services.xml`, `install-profiles.xml` и `theme.txt` копируются из `%LOCALAPPDATA%\BARS\ServiceManager3000` в `%LOCALAPPDATA%\BARS\Bars Service Manager 3000`. Исходные файлы сохраняются, имеющиеся новые настройки не перезаписываются. Привязка сохранённых паролей остаётся совместимой. Каталог содержит пути .exe, а не полный журнал установок с датами.

## Управление выбранной службой

Выдели нужную строку таблицы. Кнопки под таблицей относятся к **выделенной службе по её системному имени**:

- **«Запустить»** запускает остановленную службу, если её режим запуска не «Отключена».
- **«Остановить»** останавливает работающую или приостановленную службу, которая принимает процедуру остановки.
- Выбери режим запуска и нажми **«Применить»**: автоматически, автоматически с отложенным запуском, вручную или отключена.

Изменение режима запуска не перезапускает службу. Для каждой операции Windows может запросить права администратора. Утилита ждёт результат и проверяет его повторным чтением состояния.

Кнопки запуска и остановки недоступны, пока состояние не проверено, операция выполняется или служба находится в переходном состоянии. Сбор логов доступен и для остановленной, отключённой или переходящей между состояниями службы. Если Windows не разрешает остановку из-за зависимых служб, утилита покажет ошибку и не будет останавливать зависимости автоматически.

Выделенная строка и выбранный, но ещё не применённый режим сохраняются при автоматическом обновлении. При переходе на другую службу список режима запуска показывает настройки новой службы.

## Сбор логов в ZIP

1. Выдели службу в таблице и нажми **«Собрать логи»**.
2. Выбери **«Все логи»**, **«Только за сегодня»** или **«Выбранные даты»**. В последнем режиме отметь одну или несколько папок; выбор сохраняется при переходе между страницами.
3. Нажми **«Выбрать путь...»**, выбери папку и имя архива в стандартном окне сохранения Windows.

Программа берёт папку `Logs` рядом с .exe именно выбранной строки. Собираются `.log` и `.txt`, включая вложенные папки; структура каталогов и кириллица сохраняются. Конфигурации, библиотеки и файлы других расширений в архив не попадают.

Режим «Сегодня» определяется по имени папки, а не по времени изменения файла. Поддерживаются имена `yyyy.MM.dd`, `yyyy-MM-dd`, `yyyy_MM_dd`, `dd.MM.yyyy`, `dd-MM-yyyy`, `dd_MM_yyyy` и `yyyyMMdd`. Другие папки можно выбрать вручную по имени или включить режим «Все»; файлы непосредственно в `Logs` входят только в «Все».

Предложенное имя ZIP содержит системное имя службы, выбранную дату либо отметку «все»/«выбранные даты», дату и время сборки. Например: `BarsHttpService_Логи_за_2026-10-15_собрано_2026-10-15_17-00-00.zip`.

Служба продолжает работать. Открытые для совместного чтения логи копируются в пределах размера на момент открытия каждого файла. Если источник недоступен или исчез во время чтения, готовый архив не выдаётся за полный: программа показывает ошибку. Ссылки и точки повторной обработки пропускаются, чтобы не выходить за пределы дерева `Logs`.

Сбор выполняется в фоне. Кнопка временно меняется на **«Отменить сбор»**; закрытие программы также отменяет сбор перед выходом. Незавершённый ZIP удаляется, а существующий архив заменяется только после успешного завершения. Если папки или подходящих файлов нет, причина отображается в статусе и журнале.

## Если .exe процедуры остаётся работать

Некоторые .exe, в том числе наблюдавшаяся версия PaymentProcessing 0.14.1, продолжают работать после установки или удаления регистрации. Менеджер проверяет регистрацию во время ожидания: после двух последовательных чтений ожидаемого состояния он возвращает управление пользователю и сообщает, что процесс .exe ещё открыт, а код выхода неизвестен. Это предупреждение, а не сообщение об успешном завершении процесса.

Во время обычной процедуры `-i` / `-u` кнопка обновления меняется на «Прекратить ожидание». Она прекращает ожидание, проверяет регистрацию и возвращает управление; внешний процесс не останавливается. Если ни завершения, ни ожидаемой регистрации нет, ожидание ограничено двумя минутами, после чего также проверяется состояние службы. В особом режиме .NET действуют отдельные ограничения времени защищённого установщика.

## Установка HttpService с учётной записью

Менеджер автоматически распознаёт имя файла `HttpService.exe` и выбирает режим .NET, если для этого .exe ещё не сохранены другие настройки. Появляется сообщение: **«Сверхособенный режим установки кривонаписанной службы с выбранной учётной записью»**. Ключ профиля — полный путь .exe: настройки разных копий не смешиваются.

При первой установке откроется выбор учётной записи. В списке пользователей показаны включённые локальные пользователи Windows с полными именами и текущая учётная запись, в том числе доменная. Имя проверяется через Windows SID, вводить его вручную не требуется. Если Windows не разрешает прочитать локальный список, остаётся текущая учётная запись и показывается причина; весь каталог Active Directory не загружается.

Введи пароль выбранного пользователя. Флажок **«Запомнить пароль на этом компьютере»** необязателен: пароль сохраняется только в виде шифротекста DPAPI CurrentUser, привязанного к .exe и имени пользователя. Без флажка пароль понадобится при следующей установке. Чтобы удалить сохранённый пароль, сними флажок и сохрани настройки. Повреждённый или недоступный шифротекст приводит к повторному запросу пароля.

Кнопка **«Настройка установки»** позволяет заранее сохранить профиль, сменить пользователя или выбрать LocalService, NetworkService, LocalSystem. Выбранный тип учётной записи применяется явно; автоматического повышения до LocalSystem нет. Профили хранятся в `%LOCALAPPDATA%\BARS\Bars Service Manager 3000\install-profiles.xml`.

Режим .NET вызывает встроенные установщики сборки через отдельный повышенный процесс, сохраняя события установки и обработку отката. Для HttpService сохраняется его обработчик добавления `-s` к пути службы. Пароль не передаётся в аргументах процесса, не пишется открытым текстом в настройки и журналы: используется локальный канал с ограниченным доступом и проверкой процессов. Удаление регистрации использует соответствующий установщик и не требует пароля пользователя.

Остальные .exe по умолчанию используют обычные `-i` / `-u`. Режим .NET можно включить вручную только для совместимого .exe .NET Framework со встроенным `ServiceProcessInstaller`; он не заменяет произвольную логику всех сторонних установщиков.

## Оформление BARS

В заголовке окна — `Bars Service Manager 3000`. По центру окна расположен логотип BARS; барсик используется в значке окна и самого .exe. Логотипы встроены в программу, отдельные файлы для запуска не требуются.

Справа вверху расположен один переключатель с иконками солнца и луны. Нажми его, чтобы сменить тему. В обеих темах используются зелёный `#00824C` и тёмный `#37352F` из SVG. Для читаемости вспомогательные оттенки различаются между темами. Выбранная тема сохраняется в `%LOCALAPPDATA%\BARS\Bars Service Manager 3000\theme.txt`.

У логотипа нет рамки или подложки. В тёмной теме используется прозрачный вариант со светлыми деталями, при этом фирменный зелёный цвет и рисунок сохранены. При наведении появляется подсказка «Официальный сайт». Нажатие на логотип открывает [сайт ДАТАКРАТ](https://www.datakrat.ru/) в браузере по умолчанию. Интерфейс и журнал обращаются на «ты» и используют название «.exe службы BARS».

Сводка регистрации, процедуры установки/удаления, таблица и управление выделенной службой объединены в одну карточку. Текст сводки выровнен по левому краю таблицы; элементы управления центрированы по вертикали. Логотип центрирован по обеим осям в верхней области.

Размеры строк, столбцов и шапки таблицы нельзя менять мышью. Столбцы нельзя переставлять. Область таблицы имеет фиксированную высоту; длинный текст переносится, все записи доступны вертикальной прокруткой. Полные значения также доступны в подсказках при наведении. Основное окно можно менять в размере; при недостатке места появляется прокрутка всего содержимого.

В журнале используется узкий закруглённый ползунок без стрелок. Он появляется, когда записи не помещаются, и меняет цвета вместе с темой. Журнал можно прокручивать колесом, перетаскиванием ползунка и клавиатурой; выделение и копирование текста сохраняются.

Кнопка **«О программе»** внизу справа имеет полноценную высоту и отступ от журнала. Основной текст окна сведений выровнен по центру; фраза «Сделано с помощью вражеской нейросети.» расположена внизу слева на одном уровне с кнопкой «Ясненько всё». Окно использует выбранную тему.

Тёмная рамка заголовка зависит от поддержки этой функции вашей версией Windows. Системные диалоги прав администратора и выбора файла оформляет сама Windows.

## Возможности

- Выбор .exe через диалог или перетаскивание и общий сохраняемый список служб из всех запомненных .exe.
- Запуск точных процедур `"полный путь к программе.exe" -i` и `"полный путь к программе.exe" -u`.
- Рабочая папка запуска — папка выбранного .exe: программа сможет найти свои относительные файлы и настройки.
- Права администратора запрашиваются для процедуры; окно утилиты работает с обычными правами, чтобы принимать перетаскивание из Проводника.
- Определение регистрации по пути исполняемого файла службы, а не по совпадению имени файла или наличию процесса.
- Показ всех найденных служб, если один .exe обслуживает несколько служб.
- Отображение состояния: работает, остановлена, запускается и т. д. Остановленная служба считается зарегистрированной.
- Обновление статуса вручную и переключателем «Автообновление · 10 с». При каждом запуске автоматическое обновление включено. Первое чтение списка выполняется всегда. После процедуры таймер возобновляется только при включённом переключателе; ручное отключение сохраняется до закрытия программы.
- Повторная проверка регистрации после выполнения процедуры. Код выхода `0` без ожидаемого изменения регистрации не считается подтверждённым результатом.
- Обработка отмены запроса UAC, ошибок запуска и ошибок чтения системных данных.
- Журнал текущего сеанса, текст из которого можно скопировать.
- Кнопка **«Открыть службы»** открывает штатную оснастку Windows.

## Что означают статусы

**«Регистрация не найдена»** — среди доступных для чтения служб нет прямой ссылки на выбранный .exe.

**«Служба зарегистрирована»** — найдена как минимум одна служба с этим .exe. Текущее состояние каждой службы указано в таблице.

**«Статус регистрации неизвестен» / «Статус не удалось проверить»** — данных недостаточно. Ошибка доступа не превращается в сообщение об отсутствии службы. Установка до успешной проверки недоступна.

**«Результат не подтверждён»** — процедура закончилась, но ожидаемое изменение регистрации пока не обнаружено. Проверь журнал службы BARS и обнови статус. Windows может отложить удаление до остановки службы и закрытия открытых дескрипторов, включая оснастку «Службы».

## Границы работы

- В обычном режиме .exe должен сам поддерживать `-i` и `-u`. Особый режим требует встроенных совместимых установщиков .NET Framework. Утилита не добавляет поддержку служб произвольной программе.
- Используется локальный компьютер. Удалённые компьютеры и пакетная установка нескольких .exe не входят в эту версию.
- Установка не копирует .exe в другое место. Выбирай файл из папки, в которой он должен постоянно находиться.
- Запуск, остановка и режим запуска управляются через штатный диспетчер служб Windows. Дополнительные действия самих `-i` / `-u` определяет ваша программа.
- Если один .exe регистрирует несколько служб, `-u` может удалить сразу несколько регистраций. Выделенная строка таблицы не ограничивает действие ключа.
- Сопоставление относится к .exe, указанному непосредственно в системной конфигурации службы. Обёртки NSSM/WinSW, размещение внутри `svchost.exe`, нестандартные загрузчики, ссылки и переименованные/перемещённые файлы могут требовать отдельной логики.
- Для нестандартных прав доступа Windows показывает только доступные данные. Утилита сообщает об обнаруженной неполноте проверки, но не может гарантировать видимость служб, которые полностью скрыты от текущей учётной записи.
- У каждой программы собственные правила кодов выхода. При ненулевом коде утилита сообщает ошибку и отдельно показывает обнаруженное состояние регистрации.
- Журнал утилиты показывает выполненную процедуру, код выхода и проверку регистрации. Вывод stdout/stderr повышенного процесса не перехватывается; подробные ошибки ищи в собственном журнале службы BARS.

## Требования и исходный код

Windows 10/11 с установленным **.NET Framework 4.8 или 4.8.1**. Python, .NET SDK и отдельные библиотеки устанавливать не нужно. На Windows Server следует отдельно проверить доступность графического интерфейса и .NET Framework.

Для запуска и передачи на другой компьютер нужен только `Bars Manager 3000 2.3.13.exe`. Установщики x86/x64 встроены в него; внешний `.config` не требуется. Разрядность установщика выбирается автоматически по метаданным службы. В репозитории также находятся исходники C#, изображения и скрипт сборки `Build.ps1`.
Чтобы пересобрать программу, открой PowerShell в папке архива и выполни `./Build.ps1`. Скрипт использует компилятор, входящий в .NET Framework. Администраторские права для сборки не требуются. Если корпоративная политика запрещает скрипты, используй принятый в компании способ сборки.

`src/Program.cs` — окно и выполнение процедур; `src/ServiceCore.cs` — чтение служб и сопоставление путей; `src/ServiceManagement.cs` — запуск, остановка и режим запуска; `src/ManagedServiceStore.cs` — сохранение общего каталога; `src/Theme.cs` — темы и элементы интерфейса; `src/JournalControls.cs` — прокрутка журнала; `src/AboutDialog.cs` — окно сведений о программе. Исходники тестов находятся в `tests/`. Папка `assets/` содержит исходные SVG и подготовленные изображения, необходимые для повторной сборки.

`src/ServiceLogArchive.cs` и `src/LogArchiveDialog.cs` отвечают за ZIP и выбор дат; `src/ServiceInstallProfile.cs`, `src/ServiceProfileInstaller.cs`, `src/ServiceAccountDialog.cs` и `src/WindowsAccountInfo.cs` — за профили, защищённую передачу пароля и список пользователей Windows.

Подписанная сборка находится в `signed/`: самоподписанный сертификат Шаклеина Павла Эдуардовича, SHA-256, метки времени DigiCert; подписаны также встроенные установщики. Для повторной подписанной сборки — `./Build.ps1 -Sign`. Без `-Sign` сборка остаётся неподписанной. Самоподписанная подпись не даёт автоматического доверия Windows. Инструкция по подписи, проверке и резервной копии ключа — в [SIGNING.md](SIGNING.md).

## Проверка этой сборки

Проверены сборка, создание окна, разбор путей с пробелами и кириллицей, параметры запуска и состояния интерфейса. Подробности — в `TEST-RESULTS.md`.

Для запуска включённых проверок выполни `./Test.ps1`. Если временная папка ограничена политикой среды, укажи доступную рабочую папку: `./Test.ps1 -BuildDirectory 'C:\путь\к\папке\тестов'`. Проверки используют подставные данные и отдельные файлы каталога, не выполняя процедуры над реальными службами.

У HttpService 1.24 прочитаны метаданные и код установщика без выполнения .exe. Реальная установка этой сборкой пока не проверена: при разработке службы не создавались, не удалялись, не перезапускались и не перенастраивались. Примеры в скриншотах используют подставные данные.
