Сертификат **самоподписанный**. Он позволяет проверять целостность файла и соответствие подписи определённому ключу, но Windows не доверяет ему автоматически. Предупреждения UAC/SmartScreen могут сохраняться. Метка времени не делает издателя доверенным. Для публичного распространения с автоматическим доверием Windows нужен сертификат от доверенного удостоверяющего центра; эта бесплатная локальная подпись его не заменяет.

Доверенные хранилища Windows не изменялись. Не нужно предлагать всем пользователям безусловно устанавливать новый корневой сертификат ради запуска программы.

## Где находятся файлы и ключ

- `C:\ServiceManager3000\signed\Bars Service Manager 3000.exe` — подписанная сборка.
- `C:\ServiceManager3000\signing\Pavel-Shaklein-CodeSigning.cer` — открытый сертификат. Его можно распространять, закрытого ключа в нём нет.
- `Cert:\CurrentUser\My\5E05A9087A2BA3FF1186A72825CCA1B40B73B7EB` — сертификат с закрытым ключом в личном хранилище Windows текущего пользователя. `certmgr.msc` → «Личное» → «Сертификаты».
- `%LOCALAPPDATA%\BARS\Bars Service Manager 3000\signing.json` — только отпечаток и путь к открытому сертификату. Это не резервная копия ключа.

Отпечаток SHA-1, используемый Windows как идентификатор сертификата:

```text
5E05A9087A2BA3FF1186A72825CCA1B40B73B7EB
```

SHA-1 здесь обозначает идентификатор сертификата; файлы подписываются SHA-256. Закрытого ключа и PFX в папке проекта нет. Удаление профиля Windows или перенос только папки проекта на другой компьютер не перенесёт ключ.

## Начало работы

Открой **Windows PowerShell 5.1** обычным пользователем, под которым создан ключ. Права администратора для подписи собственных файлов не нужны.

```powershell
Set-Location C:\ServiceManager3000
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

Политика меняется только для текущего окна. При корпоративных ограничениях используй разрешённый организацией способ запуска. Скрипты используют встроенные средства Windows; Windows SDK, OpenSSL и отдельные установщики не нужны.

## Собрать и подписать нашу программу

Закрой запущенный экземпляр, если хочешь заменить именно его файл.

```powershell
.\Build.ps1 -Sign -OutputDirectory C:\ServiceManager3000\signed
```

Скрипт сначала подписывает помощников x86/x64, затем встраивает их и подписывает основной файл. Поэтому после сборки достаточно одного .exe. Обычная команда `Build.ps1` без `-Sign` по-прежнему создаёт неподписанную сборку.

Нельзя подписывать извлечённые помощники отдельно после встраивания: изменится их содержимое, проверяемое менеджером. Правильный порядок уже реализован в `Build.ps1 -Sign`.

## Подписать другой свой .exe

```powershell
.\tools\Sign-File.ps1 -FilePath 'C:\Мои программы\Моя программа.exe'
```

Можно указать несколько файлов:

```powershell
.\tools\Sign-File.ps1 -FilePath 'C:\Мои программы\Первая.exe','C:\Мои программы\Вторая.exe'
```

Сначала подписывается временная копия рядом с файлом. Исходный файл заменяется только после успешной проверки подписи и наличия метки времени. Предыдущая подпись, если она была, заменяется — это не добавление второй подписи. Работай с собственными сборками или файлами, которые уполномочен подписывать.

Для автоматического получения метки времени нужен интернет. По умолчанию используется `http://timestamp.digicert.com`; сервер получает запрос с хешем, а не исходники или закрытый ключ. Если сервер недоступен, скрипт остановится. Необязательный вариант **без метки времени**, выбранный явно:

```powershell
.\tools\Sign-File.ps1 -FilePath 'C:\Мои программы\Моя программа.exe' -TimestampServer ''
# Или собрать нашу программу без меток времени:
.\Build.ps1 -Sign -OutputDirectory C:\ServiceManager3000\signed -TimestampServer ''
```

Без метки времени нельзя рассчитывать на сохранение действительности подписи после окончания срока сертификата. Даже с меткой остаются отдельными условия доверия к сертификату, его отзыв и политика Windows.

После любого изменения подписанного файла подпись нужно создавать заново. Архивирование подписанного .exe в ZIP/7z подпись самого файла не меняет.

## Проверить подпись

```powershell
.\tools\Test-FileSignature.ps1 -FilePath 'C:\ServiceManager3000\signed\Bars Service Manager 3000.exe' `
    -CertificateThumbprint '5E05A9087A2BA3FF1186A72825CCA1B40B73B7EB'
```

Для текущей сборки ожидается:

- `SignatureChecked: True` — проверка Authenticode прошла, включая проверку целостности.
- `TrustedByWindows: False`, `VerificationCode: 0x800B0109` — ожидаемый недоверенный корень самоподписанного сертификата. Скрипт допускает именно этот результат только для самоподписанного сертификата; другие ошибки отклоняются.
- `Timestamped: True` — метка времени присутствует.

Проверка использует локальный WinVerifyTrust, без сетевой проверки отзыва сертификатов. Это не проверка на вирусы и не обещание отсутствия предупреждений SmartScreen.

Встроенная команда Windows:

```powershell
Get-AuthenticodeSignature -LiteralPath 'C:\ServiceManager3000\signed\Bars Service Manager 3000.exe' |
    Format-List Status,StatusMessage,SignerCertificate,TimeStamperCertificate
```

Для этой самоподписанной цепочки PowerShell может показывать `UnknownError` с текстом о недоверенном корневом сертификате. Это отличается от `HashMismatch` — повреждения содержимого файла. Не считай произвольный `UnknownError` нормальным: наш проверяющий скрипт проверяет точный код Windows.

Ручная проверка: Проводник → правой кнопкой по .exe → «Свойства» → «Цифровые подписи» → выбрать автора → «Сведения». Посмотри имя, сертификат и метку времени. Windows может сообщать о недоверенной цепочке — это ожидаемо до отдельного решения о доверии.

## Сделать резервную копию закрытого ключа — выполни самостоятельно

Укажи существующую защищённую папку, лучше на отдельном носителе:

```powershell
.\tools\Backup-SigningKey.ps1 -Destination 'E:\Мои ключи\Pavel-Shaklein-CodeSigning.pfx'
```

Скрипт запросит пароль скрытым вводом; минимум 12 символов. PFX защищается AES256/SHA256. Пароль не передаётся параметром командной строки и не записывается в проект. Резервная копия **ещё не создана**, поскольку пароль задаёшь ты.

Не публикуй PFX, не клади его рядом с раздаваемым .exe и не отправляй пароль в чат. Получивший PFX и пароль сможет подписывать файлы от имени этого сертификата. Храни пароль отдельно от резервной копии.

Ручной способ: Win+R → `certmgr.msc` → «Личное» → «Сертификаты» → твой сертификат → «Все задачи» → «Экспорт» → **экспортировать закрытый ключ** → PFX → защита паролем. После экспорта проверь, что резервную копию удаётся открыть выбранным паролем, прежде чем удалять старый профиль Windows.

## Перенести ключ на другой компьютер

Можно открыть PFX двойным щелчком и импортировать для **текущего пользователя**, в «Личное». Либо в Windows PowerShell:

```powershell
$keyPassword = Read-Host 'Пароль PFX' -AsSecureString
try {
    Import-PfxCertificate -FilePath 'E:\Мои ключи\Pavel-Shaklein-CodeSigning.pfx' `
        -CertStoreLocation Cert:\CurrentUser\My -Password $keyPassword -Exportable
} finally { $keyPassword.Dispose() }
```

На новом компьютере можно явно указать прежний отпечаток, без создания другого сертификата:

```powershell
.\Build.ps1 -Sign -OutputDirectory C:\ServiceManager3000\signed `
    -CertificateThumbprint '5E05A9087A2BA3FF1186A72825CCA1B40B73B7EB'
.\tools\Sign-File.ps1 -FilePath 'C:\Мои программы\Моя программа.exe' `
    -CertificateThumbprint '5E05A9087A2BA3FF1186A72825CCA1B40B73B7EB'
```

`.cer` закрытого ключа не содержит и для подписывания не подходит. Импорт в «Личное» не добавляет доверие к издателю.
