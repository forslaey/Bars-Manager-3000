# Действующие правила разработки и проверки — 13.11.2026

Этот раздел и более поздние прямые указания пользователя имеют приоритет. Записи о старых выпусках сохраняются как история. Действующие правила оформления, публикации и очистки из остальных разделов дополняют этот раздел.

## Облака, архивы и публикация файлов

- Для утилит читать _tools на Google Диске и Яндекс Диске независимо. Имена, размеры и версии могут отличаться. Размер из каталога выбранного источника использовать для проверки полноты передачи. Совпадение размера не подтверждает совпадение содержимого.
- Различать отсутствие файла, читаемую локальную копию, подтверждённое совпадение и ошибку чтения. Читаемую копию без подтверждённого совпадения оставлять доступной для распаковки и не выбирать автоматически для замены. При наличии контрольной суммы сверять её до публикации.
- Докачивать частичный файл из другого облака только при подтверждённой идентичности копии и поддержке Range. Для независимых каталогов предлагать просмотреть наборы другого облака. Успешно сохранённые файлы оставлять на месте. При неполном каталоге Google указывать конкретную папку. Пагинация пока не поддерживается.
- Сетевые сбои, повреждение архива и отмену различать по типу результата. Не определять причину по русскому тексту. В журнале называть фактическое облако и файл. В окне повреждённых архивов выводить одну фразу «Выбранные архивы скачаны не будут — они повреждены.» и список имён. Подробности оставлять в журнале.
- Для утилит поддерживать ZIP, RAR и 7z. RAR и 7z используют системный tar.exe. Таблица читает архивы в отменяемой фоновой задаче. Одно чтение каталога использовать для списка и путей ярлыков. Пути ярлыков нормализовать так же, как пути при распаковке.
- До публикации скачанного архива проверять его данные. Для ZIP регрессия должна включать читаемый каталог с испорченными данными записи. Текущий контроль CRC зависит от tar.exe. Без него чтение и проверка длины записи могут пропустить повреждение без изменения длины.
- Прогресс без известного объёма показывает этап без выдуманных процентов. Текущие пределы ожидания tar.exe: 30 секунд для чтения списка и 30 минут для проверки и распаковки. При отмене завершать собственный процесс.
- Распаковывать во временный каталог на том же диске и публиковать после успешной проверки. При разрешённой замене беречь прежнюю папку до публикации. Ошибка удаления прежней папки после публикации — отдельное предупреждение. Сверять этот сценарий в утилитах и SQL.

- Отмена сверки распространяется на чтение таблицы. Результаты предыдущей сверки сохранять до успешного чтения нового списка. «Перепроверить файлы» включать после получения каталога.
- Ошибку отдельного архива отражать в его строке и продолжать сверку. Отличать повреждение, недоступный файл и отсутствие tar.exe. Ошибка очистки временной папки не должна подменять ошибку распаковки или отмену.

## Состояния окон, справка и оформление

- Сбой чтения списка установленных программ сохранять в диагностике. Зависимым проверкам в том же сканировании возвращать неизвестное состояние с причиной. Не перечитывать список для каждого компонента после сбоя.
- Тумблер диагностики службы отражает фактическое состояние опроса. При остановке из-за исключения выключать и таймер, и тумблер.
- В фирменном выборе пути одно касание выделяет строку. Двойное касание и двойной щелчок открывают папку или выбирают файл. Свайп только прокручивает. Введённый адрес имеет приоритет перед выделением. Боковые кнопки мыши идут по истории папок.
- В локальной новогодней сборке использовать один сезонный ресурс в обеих темах во всех окнах WinForms с баннером BARS. Сохранять пропорции, центрирование и отступы. Снег рисовать по бокам в пределах баннера с учётом настройки анимации Windows. Проверять тему, фон, размеры и область анимации.
- Встроенную инструкцию и docs/USER-GUIDE.md обновлять вместе с изменением поведения. В текстах Wiki обращение на «ты», простые объяснения и точные названия кнопок. Утверждённое оформление сохранять при правках содержания.

## Регрессия и отчёт

- Для изменений функций запускать целевые сценарии и обновлять ожидания, если согласованное поведение изменилось. Для итоговой комплексной проверки запускать Test.ps1 и отдельный Test.ps1 -FindingsAudit. Прогоны UI запускать последовательно в одной сессии Windows, чтобы тесты не конкурировали за ввод, фокус и таймеры.
- Для архива проверять читаемый и повреждённый файл, ZIP с повреждёнными данными, настоящие RAR и 7z, внешнюю папку с именем архива, замену, отмену и сохранение готовых файлов. Для облаков проверять одинаковый размер при разном содержимом, неполный каталог и смешанную очередь с фактическим источником в журнале.
- Проверять две темы, компактный и развёрнутый размеры, вертикальный экран, 100/125/150/200% при моделировании, крайние положения полос, касание, двойное касание и свайп. Отдельно указывать, что проверено на физическом КСО.
- Фиксировать версию, имя набора, итог, журнал и первое упавшее утверждение. Успешный отдельный повтор не превращает упавший полный прогон в успешный. Для нестабильного теста сначала проверить условия запуска, затем искать причину. Тайминги UI проверять по достижению состояния с ограниченным ожиданием, сохраняя проверку самого результата.
- В последнем полном прогоне нестабильно упал BrandInteractionTests на затемнении кнопки, а четыре отдельных запуска прошли. Ui2329Tests однажды упал на геометрии таблицы и прошёл в финальном прогоне. Оба случая сохранять в отчёте до подтверждённого устранения.
- В отчёте отделять результаты автоматических проверок, ручные проверки и наблюдения по коду. Явно перечислять непройденные сценарии и границы покрытия, включая живые облака, физический КСО, чистую Windows без Framework и реальные установщики.
- Рабочие файлы и настройки тестировать в изоляции. При публикации сверять удалённый коммит и тег, три вложения и SHA-256 обратной загрузки. Для запрошенной подписанной сборки дополнительно сверять Authenticode и метку времени скачанного EXE. После проверки оставлять один актуальный опубликованный релиз, сохраняя теги и историю.

# Распаковка комплектов
- Для пользовательских ZIP переиспользовать PackageZipExtraction, для утилит с RAR и 7z — ToolArchives. Использовать короткое имя временного каталога на том же томе и раскрывать единственную обёртку, только если она совпадает с именем архива и охватывает все записи. Сохранять остальную вложенность.
- Проверять относительные пути и запрет выхода из каталога, распаковывать без перезаписи во временной папке, публиковать готовую папку после полной записи и учитывать разрешённую замену. При ошибке и отмене удалять только временную папку. Проверять длинные вложенные пути, в том числе в рабочем расположении пользователя.
- Для длительной распаковки использовать DownloadProgressView в обеих темах. Считать реально записанные байты, показывать 100% после публикации. При отмене или ошибке сохранять долю и показывать красный статус. Для запуска внешнего мастера полосу распаковки скрывать.

## Геометрия и оформление
- Использовать фирменные элементы, текущую светлую/тёмную тему и существующие подтверждения BrandMessageBox. Новое модальное окно не должно быть неоправданно большим, с лишними пустотами, кривыми кнопками или переносом их подписей.
- Эталон действий и интервалов — основное окно «Загрузка комплекта»: одинаковые кнопки в своей группе, одинаковые промежутки, нормальная высота и центрированный однострочный текст. Увеличение таблицы/окна не растягивает кнопки по высоте.
- Строка пути строго горизонтальная: название — поле ввода — кнопка. Вертикальные центры совпадают; видимые зазоры от поля до надписи и до кнопки равны. Поле может быть ниже широкой кнопки по высоте. Верхнюю кнопку не приравнивать к нижним действиям. Не возвращать подпись над полем.
- Правый край последней нижней кнопки совпадает с правым краем таблицы, не с внешним краем полосы прокрутки. Сохранять аккуратный зазор над кнопками и небольшой нижний отступ, без большой пустой панели снизу.
- Не менять согласованные положения остальных модулей попутно. Последнее указание пользователя по конкретному модулю приоритетнее прежних общих ориентиров (например, выравнивание отметки удалённого доступа — по правилам 2.3.48, не старой привязке к центру кружков).

Полные названия сохранять по возможности; неизвестное длинное имя не является поводом растягивать действия или обрезать другие элементы.

## Выбор, сенсорное управление и загрузки
- Во всех загрузках использовать единый фирменный блок прогресса: этап и процент над полосой, объём/скорость/оценка времени и имя файла ниже. Сохранять высоту блока с DPI, выравнивание по рабочей области/карточке, фиксированные нижние действия. Не показывать выдуманный процент установки или 100% до проверки и сохранения; пауза без движения, неизвестный размер без процентов.
- В библиотеках, установке программ и обновлениях .NET отметка переключается нажатием по всей строке, не только кружку; повторное нажатие снимает её, двойного переключения нет. Существующие ограничения доступности и busy сохранять.
- Во всех прокручиваемых списках и текстовых областях проверять свайп. Короткое касание выбирает/нажимает, свайп только прокручивает без случайных отметок. Мышь, клавиатура и копирование текста не ломаются. Включённый флаг touch не выдавать за физическое испытание КСО.
- После скачивания пересчитывать отметки, подписи и доступность кнопок; не оставлять «Снять выбор» при отсутствии выбранных файлов. Автопереход к текущему пакету — при начале файла, не на каждом блоке и не с постоянным перехватом ручного свайпа.
- При проблемах облака предлагать докачать подтверждённый остаток из другого источника или открыть его независимый каталог утилит. Готовые проверенные файлы сохранять, части продолжать только при совпадении идентичности и поддержке Range. Не переключаться бесконечно туда-сюда.
- Журнал и подтверждения простым русским языком: назвать проблемное облако, объяснить, что сохранено и что будет скачано. Не ограничиваться сырыми исключениями/терминами SHA-256 без пояснения.
- Новую копию проверять прежде замены старой; посторонние локальные файлы и настройки не удалять. Скачивание, распаковка и установка — отдельные действия, ничего не запускать автоматически.

## Однофайловый первый запуск BARS Manager 3000

- Локальный офлайн-установщик .NET Framework 4.8 Runtime хранится в `BarsManager3000\_barsmanager3000\NDP48-x86-x64-AllOS-ENU.exe`. Подчёркивание в имени подпапки обязательно. Этот установщик распространяется отдельно от программы.
- Проверочный однофайловый EXE собирается через `tools\Build-OneFileRust.ps1 -OutputDirectory <папка>`. Для подписанной сборки используется также `-Sign`.
- Запускатель использует палитры BARS и сохранённую тему. При отсутствии Framework оператор может выбрать папку с пакетом или открыть страницу Microsoft. Перед запуском локального установщика проверяется SHA-256 проверенного пакета Microsoft. При замене пакета сверять подпись и обновлять утверждённый хеш.

- Для распространяемого однофайлового EXE используется только Rust-запускатель. Build.ps1 собирает внутренний C#-менеджер для упаковки и тестов. Нужны Cargo с целью x86_64-pc-windows-gnu и утилита PE-ресурсов rsrc.exe.
- Основной локальный EXE каждой сборки размещать в bin. Использовать tools/Build-OneFileRust.ps1. Внешний EXE должен содержать значок и сведения о версии и продукте из C#-сборки. Ресурсы добавляются до подписи.
