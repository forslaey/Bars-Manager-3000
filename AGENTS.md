# Работа над BARS Manager 3000

Репозиторий: https://github.com/forslaey/Bars-Service-Manager-3000
Основная ветка: main. Текущая версия: 2.2.0 (версия для проверки новых функций).

Перед изменениями прочитай DEVELOPMENT-STATE.md, MANAGER-V2.md и текущий RELEASE-*.md.
Исходники C# WinForms находятся в src/, тесты в tests/. Сборка: Build.ps1; проверки: Test.ps1.
Windows 10/11 и Server 2019+ с рабочим столом; baseline .NET Framework 4.6.

## Требования пользователя

- Библиотеки: название самого модуля Bars Component Manager 3000; в карточке и кнопке общего лаунчера — «Менеджер компонентов» по просьбе пользователя. Службы сохраняют своё имя.
- Светлая и тёмная фирменные темы; читаемый текст, ровные рамки, удобная область клика.
- RuntimePack Full исключён. Встроенный Lite обязателен в обоих профилях VC++.
- Учитывай полные версии, архитектуру и поколение компонентов. Не понижай новые версии старым комплектом.
- Отмена и выход требуют предупреждения, завершают только процессы собственного задания.
  Не завершай общую службу Windows Installer и чужие процессы по имени.
- Не запускай настоящие установки/удаления библиотек или операции служб ради тестирования без отдельного указания пользователя.
- Отдельное разрешение на реальные испытания получено 19.10.2026: создана изолированная Hyper-V VM BARS-Test-W11 (гостевое имя BARS-LAB-01). Реальные установки/удаления для испытаний проводить внутри неё; рабочие компоненты хоста не трогать. Состояние и доступ описаны в TEST-LAB.md.
- По умолчанию собирай БЕЗ цифровой подписи, включая встроенные помощники. Не создавай новый сертификат вместо прежнего.
- При публикации всегда включай ПОДПИСЬ-ПОШАГОВО.txt и СКОМПИЛИРОВАТЬ.txt; поддерживай их актуальность.
- Перед завершением значимого изменения обнови DEVELOPMENT-STATE.md: что сделано, как проверено и что ещё не проверялось.

## Работа с двух компьютеров

Перед началом проверь git status и получи актуальный main. Не стирай локальные изменения и не перезаписывай чужую работу.
После изменений, которые пользователь попросил опубликовать, сделай коммит и обычный push без force.
Не включай закрытые ключи/PFX, пароли, пользовательские конфигурации, журналы или внешние установщики библиотек.
Готовые согласованные неподписанные релизы хранятся в releases/<version>/; временные bin/work игнорируются.

## Новые модули 2.2.0

- WindowsComponents.cs: точный профиль 27 IIS-компонентов с компьютера пользователя, отдельные Telnet/TFTP. В UI два блока, без дерева IIS. Все включения только по кнопке, через DISM -NoRestart.
- ToolsDeployment.cs: четыре ярлыка строго Piglet (DK-QStart.exe), fiLinn (cspPanel.exe), tftpd32 (tftpd32.exe), WinSCP (WinSCP.exe), иконки из этих EXE. Для этих четырёх копий выставляется RUNASADMIN в HKCU текущего пользователя, EXE не редактируются.
- Последнее указание пользователя: до тестов реальных установщиков в VM остановиться. Сначала дать попробовать новые функции на неподписанной сборке. Это уточнение приоритетнее прежнего разрешения тестировать все библиотеки в VM.
- Установку компонентов Windows/перезагрузку на рабочем хосте ради тестов не выполнять. Явный -UtilitySmoke читает Windows и проверяет копии утилит только во временных папках.
