# Передача контекста Astra: выбор платформы BARS Manager 3000

Дата: 29.10.2026. Проект: `C:\ServiceManager3000`, репозиторий https://github.com/forslaey/Bars-Manager-3000, основная ветка `main`.

## Что пользователь уточнил

Фактически самая старая Windows на объектах — **Windows 10 21H2**, самая старая серверная ОС — **Windows Server 2022**. Более старые системы больше не используются. Обычно стоит Windows Pro на клиентах и компьютерах, выполняющих роль сервера, либо Windows Server. Роль компьютера не меняет требования платформы: важна установленная ОС. Для WinForms подразумевается Windows Server с рабочим столом, не Server Core.

Это заменяет прежнее представление о фактическом использовании Windows 10 1809 / Server 2019. Однако формальные требования проекта ещё не пересмотрены: не менять их молча.

## Приоритеты пользователя

1. Совместимость с ОС объектов.
2. Маленький распространяемый EXE.
3. Быстрый запуск с медленных флешек и работа на слабых компьютерах.
4. Сохранение функциональности и согласованного UI.
5. Большинство дополнительных возможностей современного .NET не требуется.

## Текущая технология

C# + WinForms, целевая платформа **.NET Framework 4.6**. Один распространяемый EXE со встроенными помощниками. Сборка `Build.ps1`, тесты `Test.ps1` и целевые сценарии в `tests`.

**В этом обсуждении миграция не выполнялась. Пользователь пока НЕ дал отдельного разрешения менять платформу.** Последний запрос — сохранить контекст для другого ассистента. Не считать рекомендации заданием на немедленную миграцию.

Последняя известная опубликованная версия — **2.3.60**. Перед работой проверить фактические `git status`, версию, документы и изменения пользователя: он работает из разных приложений/компьютеров.

## Проверенные сведения о Framework

По официальной таблице Microsoft:
https://learn.microsoft.com/en-us/dotnet/framework/migration-guide/versions-and-dependencies

- Windows 10 1809 / LTSC 2019 и Server 2019 изначально содержали Framework 4.7.2; 4.8 устанавливается отдельно.
- Windows 10 начиная с 1903, в том числе **21H2 Pro**, изначально содержит **Framework 4.8**.
- **Windows Server 2022** изначально содержит **Framework 4.8**.
- Windows 11 21H2 содержит 4.8; более новые выпуски могут содержать совместимый 4.8.1.
- Framework 4.8.1 нельзя делать обязательным для нашего минимума Server 2022 без отдельного рассмотрения.
- Корпоративные/модифицированные образы могут отличаться; установленную версию полезно проверять фактически.

## Вывод обсуждения

При новом минимуме ОС **Framework 4.8 — разумный кандидат для планового обновления**. На стандартных образах указанных минимальных ОС он уже есть. Сохраняются C#, WinForms, небольшой EXE без встроенной среды и возможность запуска с флешки.

Переход с Framework 4.6 на 4.8 обычно не означает переписывание всего приложения. Большая часть кода должна сохраниться. Но нельзя обещать отсутствие регрессий: особенно чувствительны DPI/масштабирование/текст/геометрия UI, TLS и сеть, помощники, UAC и установка служб.

Нельзя обещать существенное ускорение от одного изменения target framework: приложение для 4.6 на машине с Framework 4.8 уже исполняется на установленной среде 4.8. Значительного увеличения EXE только из-за retargeting обычно не ожидается, но измерение обязательно.

**Не рекомендована смена языка или переход на современный .NET self-contained ради самого перехода.** Self-contained поставляет среду вместе с приложением, заметно увеличивает комплект и требует обновлять встроенную среду при исправлениях безопасности. Single-file — отдельная настройка; ни она, ни self-contained не шифруют код. Красивый прогресс-бар можно реализовать на текущем Framework.

## Если пользователь отдельно разрешит миграцию на Framework 4.8

1. Прочитать `AGENTS.md`, актуальное начало `DEVELOPMENT-STATE.md`, `MANAGER-V2.md`, текущий `RELEASE-*.md`.
2. Проверить `git status`, актуальность удалённой ветки и чужие локальные изменения. Ничего не стирать/не перезаписывать.
3. Сохранить рабочий baseline. Для новой ветки использовать префикс `chatbox/`, если работа ведётся Chatbox-агентом.
4. Делать сначала только retargeting, без редизайна, смены языка и большого рефакторинга.
5. Проверить `Build.ps1`, `tools/Prepare-References.ps1`, явные списки reference assemblies в тестовых сценариях, TargetFrameworkAttribute и сборку всех встроенных помощников. Не достаточно поменять одну строку.
6. Получить экспериментальную сборку и сравнить с baseline: размер EXE, холодный/повторный запуск, память. Условия и носители должны быть сопоставимыми.
7. Сравнить снимки UI на одинаковых DPI и обеих темах. Соблюдать все правила `AGENTS.md`, особенно таблицы, целые строки, scrollbar, одинаковые кнопки, отступы, строки выбора папок. Не менять согласованный UI ради устаревшего теста без анализа.
8. Проверить загрузки, TLS, отмену, паузу, Range и зеркала Google/Яндекс. Не запускать скачанные пакеты автоматически.
9. Системные сценарии (службы, установки, UAC, отмена, перезагрузка) испытывать в изолированной VM и только в разрешённых пределах. Рабочую Windows пользователя не перенастраивать.
10. Целевые тесты и испытания на минимальных ОС — Windows 10 21H2 и Server 2022 Desktop. Не объявлять полный набор успешным, если прогон был частичным или есть падения.
11. Формально обновить минимальные требования и документацию после согласованного решения.
12. Выпускать только после проверок по порядку из `AGENTS.md`: готовый EXE в `bin`, по умолчанию без подписи; исходники и тесты в GitHub без force; релиз ровно EXE + RELEASE + CHANGELOG; проверка tag/commit/tree/размеров/SHA256 и обратной загрузки EXE.

## Важное о текущем рабочем дереве

Ранее в `git status` оставались пользовательские удаления старых файлов `releases/v2.3.30–36`: не восстанавливать и не включать в коммит автоматически. Сводные замечания пользователя по UI уже записаны в начале `AGENTS.md`. Последний запрос на запись всех правил изменил `AGENTS.md` локально; он мог ещё не быть отправлен в GitHub — перепроверить.

Известны отдельные падения старых общих UI-тестов (лаунчер/компактность диалога облака), а также исторические ограничения Base64/Ui2330. Их не считать доказанно исправленными. Точные актуальные ограничения брать из документов проекта.
