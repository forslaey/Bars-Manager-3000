Для этого выпуска используется прежний сертификат. Если signing.json отсутствует,
к командам Build.ps1 -Sign и tests\SigningTests.ps1 добавь:
-CertificateThumbprint 5E05A9087A2BA3FF1186A72825CCA1B40B73B7EB
Для подписи нужен его закрытый ключ в личном хранилище Windows; для проверки — не нужен.
Новый сертификат для этого выпуска создавать не следует.
Текущий выпуск 2.3.32 создан без подписи, включая встроенные помощники. Ранее опубликованный выпуск 2.3.13 подписан по отдельной просьбе пользователя.
Запуск от администратора для распакованных утилит задаётся параметром совместимости Windows и не меняет EXE или его имеющуюся подпись.
Подписывать файлы нужно только отдельным явным действием по инструкции ниже.

# Подпись, снятие подписи и сведения об авторе — пошагово

Для Bars Manager 3000. Актуализировано 27.10.2026.

Сборка 2.1.1 в C:\ServiceManager3000\bin собрана БЕЗ подписи, включая встроенные помощники. Подписывать её сейчас не требуется. Ниже описаны отдельные действия для случая, когда ты сам решишь подписать файл прежним сертификатом.

## 1. Что понадобится один раз

1. Папка проекта C:\ServiceManager3000 со всеми исходниками, Build.ps1 и папкой tools.
2. Для подписи — прежний сертификат С ЗАКРЫТЫМ КЛЮЧОМ. На рабочем компьютере его пока нет. Обычный .cer из проекта не подходит.
3. Интернет для получения метки времени DigiCert при подписании.
4. Закрой экземпляр программы, файл которого собираешься заменять.

Администратор для обычной сборки и работы с личным сертификатом не нужен. Если Windows не разрешает запись в C:\ServiceManager3000, используй папку проекта, доступную твоему пользователю, и замени её путь в командах.

### Перенос прежнего сертификата с домашнего компьютера

На домашнем компьютере войди под тем пользователем Windows, где подписывали программу:

1. Нажми Win + R.
2. Введи certmgr.msc и нажми Enter.
3. Слева открой «Личное» → «Сертификаты».
4. Найди «Шаклеин Павел Эдуардович».
5. Дважды открой сертификат → «Состав»/«Подробно» → «Отпечаток». Для прежнего сертификата он должен быть:
   5E05A9087A2BA3FF1186A72825CCA1B40B73B7EB
6. Закрой окно сертификата. Нажми по нему правой кнопкой → «Все задачи» → «Экспорт».
7. Выбери «Да, экспортировать закрытый ключ».
8. Выбери формат PFX / PKCS #12. Удаление исходного закрытого ключа НЕ включай.
9. Задай надёжный пароль. Сохрани файл на личную флешку.
10. Если пункта «Да, экспортировать закрытый ключ» нет, остановись: возможно, выбран другой сертификат, ключ недоступен или не разрешён его экспорт.

На рабочем компьютере:

1. Открой PFX двойным щелчком.
2. Выбери «Текущий пользователь».
3. Введи пароль, заданный дома.
4. Выбери размещение сертификатов в хранилище «Личное».
5. Заверши мастер. Добавлять сертификат в доверенные корневые хранилища для подписания не нужно.

PFX и пароль не размещай в проекте, GitHub или чате. .gitignore не заменяет отдельное безопасное хранение ключа.

## 2. Как открыть нужное окно для команд

Каждый раз, когда начинаешь работу заново:

1. Нажми «Пуск».
2. Напиши Windows PowerShell.
3. Открой именно «Windows PowerShell» обычным запуском. Не CMD. Установленный PowerShell 7 для этой инструкции не нужен.
4. Скопируй следующие две строки, вставь в окно и нажми Enter:

```powershell
Set-Location 'C:\ServiceManager3000'
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

Если PowerShell спросит подтверждение изменения политики, подтверди его. Настройка действует только в этом окне; системная политика не меняется. Если действует корпоративный запрет, не обходи его — используй согласованный способ запуска скриптов.

Далее вставляй только содержимое блоков команд — без строк с тройными обратными кавычками.

## 3. Проверить, что прежний ключ доступен

В том же окне выполни:

```powershell
Get-Item 'Cert:\CurrentUser\My\5E05A9087A2BA3FF1186A72825CCA1B40B73B7EB' | Format-List Subject,Thumbprint,HasPrivateKey,NotAfter
```

Нужны правильный отпечаток, HasPrivateKey : True и неистёкшая дата NotAfter. Если написано, что путь не найден, импорт ключа для этого пользователя не выполнен.

## 4. Собрать НАШ менеджер сразу с подписью — рекомендуемый способ

После переноса ключа выполни в окне из раздела 2 одну строку:

```powershell
.\Build.ps1 -Sign -CertificateThumbprint '5E05A9087A2BA3FF1186A72825CCA1B40B73B7EB' -OutputDirectory 'C:\ServiceManager3000\signed'
```

Дождись завершения без красной ошибки.

Результат:
C:\ServiceManager3000\signed\Bars Manager 3000 2.3.13.exe

Скрипт сначала подписывает встроенные установщики x86 и x64, затем встраивает их и подписывает основной EXE. Для нашего менеджера предпочтителен именно этот способ. Это замена файла в signed новой сборкой из текущих исходников.

Проверить основную подпись:

```powershell
.\tools\Test-FileSignature.ps1 -FilePath 'C:\ServiceManager3000\signed\Bars Manager 3000 2.3.13.exe' -CertificateThumbprint '5E05A9087A2BA3FF1186A72825CCA1B40B73B7EB'
```

Ожидается SignatureChecked : True, Timestamped : True и прежний отпечаток. Для нашего самоподписанного сертификата TrustedByWindows : False и VerificationCode : 0x800B0109 ожидаемы: подпись присутствует и проверена, но Windows не доверяет корню сертификата автоматически. Не путай это с отсутствием подписи или повреждением файла.

Можно проверить подписи всех трёх компонентов штатным тестом проекта:

```powershell
.\tests\SigningTests.ps1 -SignedExecutable 'C:\ServiceManager3000\signed\Bars Manager 3000 2.3.13.exe'
```

В Проводнике: правой кнопкой по EXE → «Свойства» → «Цифровые подписи» → выбери запись → «Сведения». Одна лишь вкладка не заменяет проверку подписи.

## 5. Подписать уже готовый отдельный EXE

Это не пересборка. Скрипт подписывает указанный файл на месте, заменяя прежнюю подпись, если она есть. Сначала сделай копию нужного файла.

Например, наш уже собранный файл из bin:

```powershell
.\tools\Sign-File.ps1 -FilePath 'C:\ServiceManager3000\bin\Bars Manager 3000 2.3.13.exe' -CertificateThumbprint '5E05A9087A2BA3FF1186A72825CCA1B40B73B7EB'
```

Для другого своего файла замени только путь после -FilePath. При ошибке подписи скрипт сохраняет исходный файл.

Для НАШЕГО менеджера эта команда подписывает только внешний EXE: встроенные установщики остаются в том состоянии, в котором были собраны. Чтобы подписать все компоненты, используй раздел 4.

## 6. Получить наш менеджер совсем без подписи

Выполни:

```powershell
.\Build.ps1 -OutputDirectory 'C:\ServiceManager3000\bin'
```

Результат:
C:\ServiceManager3000\bin\Bars Manager 3000 2.3.13.exe

Здесь заново собираются и внешний EXE, и оба встроенных установщика без подписания. Это новый файл из исходников, а не удаление подписи из прежнего EXE. Ничего добавлять к Build.ps1 не требуется: просто нет ключа -Sign.

Проверить:

```powershell
Get-AuthenticodeSignature -LiteralPath 'C:\ServiceManager3000\bin\Bars Manager 3000 2.3.13.exe' | Format-List Status
```

Должно быть Status : NotSigned.

## 7. Удалить подпись именно из существующего EXE

Для этого Microsoft предоставляет SignTool из Windows SDK. На рабочем компьютере он сейчас не найден в PATH. Новые компоненты автоматически не устанавливались.

1. Открой https://learn.microsoft.com/en-us/windows/apps/windows-sdk/downloads
2. Скачай установщик поддерживаемого Windows SDK.
3. В мастере выбери установку на этот компьютер; среди компонентов оставь «Windows SDK Signing Tools for Desktop Apps», если такой пункт доступен в выбранной версии.
4. После установки в PowerShell найди инструмент:

```powershell
$taskSignTool = Get-ChildItem -LiteralPath "${env:ProgramFiles(x86)}\Windows Kits\10\bin" -Filter signtool.exe -Recurse | Where-Object { $_.FullName -match '\\x64\\signtool\.exe$' } | Sort-Object FullName -Descending | Select-Object -First 1
if (-not $taskSignTool) { throw 'SignTool не найден. Проверь установку Signing Tools.' }
$taskSignTool.FullName
```

5. Создай отдельную копию подписанного файла, чтобы сохранить исходник:

```powershell
New-Item -ItemType Directory -Path 'C:\ServiceManager3000\unsigned-copy' -Force | Out-Null
Copy-Item -LiteralPath 'C:\ServiceManager3000\signed\Bars Manager 3000 2.3.13.exe' -Destination 'C:\ServiceManager3000\unsigned-copy\Bars Manager 3000 2.3.13.exe' -Force
```

6. Сними подпись только с копии:

```powershell
& $taskSignTool.FullName remove /s 'C:\ServiceManager3000\unsigned-copy\Bars Manager 3000 2.3.13.exe'
if ($LASTEXITCODE -ne 0) { throw 'SignTool сообщил об ошибке.' }
Get-AuthenticodeSignature -LiteralPath 'C:\ServiceManager3000\unsigned-copy\Bars Manager 3000 2.3.13.exe' | Format-List Status
```

Ожидается NotSigned. Сертификат в Windows не удаляется. Подписи встроенных EXE эта команда не затрагивает. Для полностью неподписанного менеджера проще раздел 6.

Документация команды remove /s:
https://learn.microsoft.com/en-us/windows/win32/seccrypto/signtool

## 8. Где менять автора, компанию, контакты и версию

Есть ТРИ разных места. Они не обновляются друг из друга автоматически.

### 8.1. Свойства EXE → «Подробно»

1. В Проводнике открой C:\ServiceManager3000\src.
2. Найди AssemblyInfo.cs.
3. Нажми правой кнопкой → «Открыть с помощью» → «Блокнот».
4. Меняй только текст внутри двойных кавычек в нужных строках:

```csharp
[assembly: AssemblyTitle("Bars Service Manager 3000")]
[assembly: AssemblyDescription("Регистрация и управление службами Windows — BARS")]
[assembly: AssemblyProduct("Bars Service Manager 3000")]
[assembly: AssemblyCompany("ДатаКрат - ОТЭиВ")]
[assembly: AssemblyCopyright("Автор: Шаклеин Павел Эдуардович; junior@aniello.ru")]
[assembly: AssemblyVersion("1.7.0.0")]
[assembly: AssemblyFileVersion("1.7.0.0")]
```

Что за что отвечает:

- AssemblyTitle — заголовок/описание файла в метаданных.
- AssemblyDescription — дополнительное описание сборки .NET; Проводник может не выводить его отдельной строкой.
- AssemblyProduct — название продукта.
- AssemblyCompany — организация.
- AssemblyCopyright — автор и контакт в нашей текущей схеме, отображаемые как сведения об авторских правах. Отдельного стандартного поля e-mail у EXE здесь нет.
- AssemblyVersion — версия сборки, её использует наше окно «О софтине».
- AssemblyFileVersion — версия файла во вкладке «Подробно».

5. Нажми Ctrl + S. Сохраняй файл в UTF-8.
6. Пересобери без подписи командой из раздела 6 либо с подписью по разделу 4.
7. В свойствах проверяй именно новый EXE из bin или signed.

Редактирование только .cs-файла не меняет готовый EXE. После изменения готового подписанного EXE его нужно подписать заново. Для версий используй четыре числовые части. При выпуске с новой версией также согласуй version в src\app.manifest.

### 8.2. Текст внутри окна «О софтине» и заголовок окна

Открой src\AboutDialog.cs в Блокноте. Там меняются видимые строки названия, подзаголовка, описания и нижнего шуточного текста. Версия берётся из AssemblyVersion автоматически.

Заголовок главного окна задаётся в src\Program.cs строкой Text = "Bars Service Manager 3000".

После сохранения обязательно собери программу заново. В настоящей версии имя автора и e-mail в окне «О софтине» отдельно не выводятся.

### 8.3. «Цифровые подписи» → имя издателя и контакты сертификата

Они записаны в самом сертификате. Изменение AssemblyInfo.cs их НЕ меняет.

В tools\New-SigningCertificate.ps1 есть шаблон -Subject:
CN=Шаклеин Павел Эдуардович, O=ДатаКрат - ОТЭиВ, E=junior@aniello.ru

- CN — имя издателя.
- O — организация.
- E — e-mail в сертификате.
- FriendlyName — только удобное название записи в хранилище Windows; это не имя издателя в уже существующем сертификате.

У уже выданного сертификата нельзя просто отредактировать CN/O/E. Для других сведений нужен другой сертификат, у него будет другой отпечаток. Изменение шаблона скрипта не исправляет уже созданный сертификат. Сам скрипт намеренно повторно использует доступный сохранённый сертификат, а не создаёт новый при каждом запуске.

Если ты ОСОЗНАННО хочешь другого издателя, а не перенос прежней подписи, можно создать отдельный самоподписанный сертификат, не удаляя старый. Это НЕ нужно для обычной смены контакта во вкладке «Подробно».

1. В окне Windows PowerShell из раздела 2 выполни следующие команды, предварительно заменив имя, организацию и e-mail на свои:

```powershell
$taskNewSigner = New-SelfSignedCertificate -Type CodeSigningCert -Subject 'CN=Фамилия Имя Отчество, O=Название организации, E=your@example.com' -FriendlyName 'Мой новый сертификат подписи' -CertStoreLocation 'Cert:\CurrentUser\My' -KeyAlgorithm RSA -KeyLength 3072 -HashAlgorithm SHA256 -KeyUsage DigitalSignature -KeyExportPolicy Exportable -Provider 'Microsoft Software Key Storage Provider' -NotAfter (Get-Date).AddYears(3)
$taskNewSigner | Format-List Subject,Thumbprint,HasPrivateKey,NotAfter
```

2. Для пробного выпуска с новым издателем в том же окне выполни:

```powershell
.\Build.ps1 -Sign -CertificateThumbprint $taskNewSigner.Thumbprint -OutputDirectory 'C:\ServiceManager3000\signed-new'
```

3. Запиши новый отпечаток. После закрытия PowerShell переменная taskNewSigner исчезнет, а сертификат останется в certmgr.msc → «Личное». В дальнейшем передавай новый отпечаток в -CertificateThumbprint явно.

Эти команды в рамках подготовки инструкции НЕ выполнялись. Прежний сертификат и настройки доверия не менялись. Новый самоподписанный сертификат не получает автоматического доверия Windows и не подтверждает сведения об организации у удостоверяющего центра.

Справка Microsoft:
https://learn.microsoft.com/en-us/powershell/module/pki/new-selfsignedcertificate

## 9. Короткая памятка

- Изменил исходники или сведения об авторе → пересобери → подпиши заново, если нужен подписанный выпуск.
- Наш менеджер целиком с подписями → Build.ps1 -Sign с правильным отпечатком.
- Наш менеджер целиком без подписей → Build.ps1 без -Sign.
- Подписать отдельный готовый EXE → tools\Sign-File.ps1.
- Снять подпись с существующего EXE → SignTool remove /s, лучше на копии.
- Переименование EXE не меняет автора, контакты и издателя.
- Контакты в «Подробно» и контакты сертификата — разные сведения.
- Ключ хранится в Windows и резервном PFX, а не в исходниках и не в GitHub.
