ПРОСТАЯ СБОРКА ДВОЙНЫМ ЩЕЛЧКОМ

1. Закрой запущенный Bars Manager 3000, чтобы файл сборки не был занят.
2. Открой папку проекта. Рядом должны быть Build.ps1, src, assets и tools.
3. Запусти один из двух файлов:
   Build-Unsigned.cmd — БЕЗ подписи; результат в папке bin.
   Build-Signed.cmd — С подписью прежним сертификатом; результат в папке signed.
4. Дождись BUILD COMPLETE. При BUILD FAILED прочитай ошибку выше.
5. Открой соответствующую папку: Bars Manager 3000 x.x.x.exe.
   Номер берётся из src\AssemblyInfo.cs. Если номер не изменён, файл этой версии
   перезаписывается. Файлы с другими номерами автоматически не удаляются.

Оба CMD используют встроенный Windows PowerShell 5.1. Устанавливать PowerShell 7
и запускать от администратора не требуется, если папка проекта доступна для записи.
ExecutionPolicy Bypass действует только на этот запуск; системная политика не меняется.
Политики организации имеют приоритет: если блокирует организация, обратись к администратору.
Для первой загрузки reference assemblies и для метки времени подписи нужен интернет.
Для Build-Signed.cmd нужен прежний сертификат с закрытым ключом в личном хранилище
текущего пользователя. Сертификат автоматически не создаётся и не импортируется.
На другом компьютере сначала перенеси прежний сертификат с закрытым ключом (PFX).
Эти CMD только компилируют; тесты, GitHub и установки компонентов не запускают.

------------------------------------------------------------
Для этого выпуска используется прежний сертификат. Если signing.json отсутствует,
к командам Build.ps1 -Sign и tests\SigningTests.ps1 добавь:
-CertificateThumbprint 5E05A9087A2BA3FF1186A72825CCA1B40B73B7EB
Для подписи нужен его закрытый ключ в личном хранилище Windows; для проверки — не нужен.
Новый сертификат для этого выпуска создавать не следует.
Имя итогового файла формируется автоматически из версии: Bars Manager 3000 x.x.x.exe.
Вторую копию под старым названием сборка больше не создаёт.

ТЕКУЩАЯ ЛОКАЛЬНАЯ СБОРКА: 2.3.16 — без подписи. Подписанный опубликованный выпуск 2.3.13 остаётся отдельным.
Новые функции, интерфейс и границы проверок: RELEASE-2.3.16.md.
Из C:\ServiceManager3000:
powershell -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1 -OutputDirectory .\bin
Результат: C:\ServiceManager3000\bin\Bars Manager 3000 2.3.16.exe
Тесты не запускают реальные установщики. Дополнительный -UtilitySmoke требует уже повышенного сеанса и читает компоненты Windows, проверяет временные копии утилит.

BARS Manager 3000 — сборка 2.1.1

1. Открой PowerShell в папке проекта (обычно C:\ServiceManager3000).
2. Обычная сборка БЕЗ подписи:

.\Build.ps1 -OutputDirectory .\bin

Результат: bin\Bars Manager 3000 2.3.16.exe. Это общий лаунчер с четырьмя карточками; Компоненты Windows открываются из менеджера библиотек.
Встроенные помощники тоже будут без подписи. Не добавляй -Sign, если подпись не нужна.
Скрипт использует reference assemblies .NET Framework 4.6; при первой сборке нужен интернет.
Исходники рассчитаны на встроенный компилятор C# .NET Framework, Visual Studio не требуется.

3. Проверки (не устанавливают и не удаляют настоящие библиотеки/службы):

.\Test.ps1

Тест отмены запускает и завершает только собственные инертные процессы.
Защищённые именованные события нужно проверять под обычной учётной записью Windows,
без урезанного токена песочницы; права администратора для самих тестов не требуются.

Если PowerShell блокирует локальные скрипты и политика не задана организацией,
для своего пользователя один раз можно выполнить:
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

4. ТОЛЬКО если решил подписать сборку прежним сертификатом с закрытым ключом:

.\Build.ps1 -Sign -CertificateThumbprint '5E05A9087A2BA3FF1186A72825CCA1B40B73B7EB' -OutputDirectory '.\signed'

Результат: signed\Bars Manager 3000 2.3.16.exe. Сначала подписываются оба встроенных
помощника, затем общий EXE. Без прежнего закрытого ключа эта команда не сработает.
Пароли и закрытые ключи в GitHub не загружай.

Пошаговые инструкции по подписи, её проверке и сведениям об авторе:
ПОДПИСЬ-ПОШАГОВО.txt

При публикации изменений оба файла ПОДПИСЬ-ПОШАГОВО.txt и СКОМПИЛИРОВАТЬ.txt
должны оставаться в репозитории.
