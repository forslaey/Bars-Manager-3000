# Продолжение разработки дома и на работе

## Ручная синхронизация двойным щелчком

Папка на обоих ПК — `C:\ServiceManager3000`. В ней должны лежать **все три файла**:
`Git-Download.cmd`, `Git-Upload.cmd` и `Git-Sync.ps1`.
Два CMD-файла лишь запускают общий PS1: переноса только этих двух файлов недостаточно.

Если появляется ошибка, что `Git-Sync.ps1` не существует, восстанови этот файл из
актуального проекта на GitHub в ту же папку. Не удаляй `.git`, не создавай новый
пустой `Git-Sync.ps1` и не запускай выгрузку неполной старой копии поверх новых
домашних изменений. Новые CMD заранее проверяют наличие PS1 и выводят подсказку.

Порядок одинаков в обе стороны:

1. Перед работой запусти **Git-Download.cmd** из папки проекта.
2. После работы запусти **Git-Upload.cmd**. Просмотри список изменений, введи `YES`,
   затем описание коммита. Enter вместо описания подставит дату и имя компьютера.
   Удалённые файлы тоже входят в коммит.
3. Дождись «Выгрузка завершена». На другом ПК запусти **Git-Download.cmd**.

Окно остаётся открытым до нажатия клавиши. Не выгружай одновременно с двух ПК.
Нужны Windows PowerShell 5.1 и Git. Скрипт ищет установленный Git и Git из текущего
комплекта Codex. Если Git не найден, установи Git for Windows. При обращении к GitHub
может потребоваться вход через Git Credential Manager/браузер. Пароли и токены
в скрипты не сохраняй. Двойной щелчок использует папку самих скриптов.

**Что переносится:** исходники, документация, ресурсы и остальные отслеживаемые Git
файлы. Новые файлы добавляются с учётом `.gitignore`. Локальные коммиты тоже отправляются.
Игнорируемые `bin`, `work`, установщики из `Библиотеки`, личные настройки, журналы
и ключи не переносятся. Это синхронизация проекта, а не полная резервная копия диска.
Согласованные релизы из `releases`, которые отслеживает Git, переносятся.
Известные имена закрытых/локальных файлов проверяются даже для отслеживаемых файлов.
Самостоятельно проверь, что в исходниках нет паролей и токенов.

**При ошибке** не удаляй файлы и `.git`. Скрипты не используют force push,
reset --hard, очистку папки и автоматическое скрытие изменений в stash.
Скачивание при локальных изменениях остановится. Если правки появились на обоих ПК
или история разошлась, передай сообщение разработчику для ручного согласования.
При ошибке отправки созданный коммит сохраняется локально: исправь связь/авторизацию
и повтори выгрузку. Если Git не знает автора, один раз выполни в папке проекта:

```powershell
git config user.name "Твоё имя"
git config user.email "Твой email GitHub или адрес noreply из настроек GitHub"
```

Рабочая ветка — `main`, сервер — `origin` существующего репозитория. Скрипты не
собирают приложение, не создают GitHub Releases и не отправляют теги.

### Первое скачивание без репозитория

Скопируй `Git-Download.cmd`, `Git-Upload.cmd` и `Git-Sync.ps1` вместе во временную
папку вне проекта, например `C:\Temp\BarsSync`. Открой там PowerShell:

```powershell
.\Git-Download.cmd -ProjectPath "C:\ServiceManager3000"
```

Если целевой папки нет или она пуста, проект клонируется из
`https://github.com/forslaey/Bars-Manager-3000.git`, ветка `main`.
Непустая папка без `.git` не перезаписывается. После клонирования запускай скрипты
из `C:\ServiceManager3000`. Чтобы они вошли в скачиваемый проект, сначала выгрузи
их на GitHub с первого компьютера.

### Дополнительные параметры

```powershell
.\Git-Download.cmd -ProjectPath "C:\ServiceManager3000"
# Готовое описание; подтверждение YES остаётся
.\Git-Upload.cmd -Message "Исправления интерфейса"
# Без подтверждений: для осознанного запуска из командной строки
.\Git-Upload.cmd -Yes -Message "Сохранение работы"
```

Общая логика — `Git-Sync.ps1`. Прямой запуск с `-Action Upload` или `-Action Download`
не ждёт клавиши в конце. `-RepositoryUrl` задаёт адрес только первого клонирования,
существующий `origin` не меняет. Проверка без сборки и доступа к GitHub:
`powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\GitSync.Tests.ps1`.

---

GitHub переносит файлы и коммиты. Переписка одного чата не становится памятью другого автоматически.
Поэтому контекст проекта хранится в AGENTS.md, DEVELOPMENT-STATE.md, MANAGER-V2.md и RELEASE-2.1.0.md.

## Первый запуск дома

1. Открой домашний Codex и передай ссылку: https://github.com/forslaey/Bars-Manager-3000
2. Попроси клонировать репозиторий локально. Если прежняя C:\ServiceManager3000 уже существует,
   сначала проверить её git status и несохранённые изменения; не перезаписывать и не удалять её автоматически.
3. Если GitHub попросит вход, авторизуй свой аккаунт через окно Git/Git Credential Manager/браузер.
   Для закрытого репозитория аккаунту нужен доступ. Одного входа в аккаунт ChatGPT для Git-доступа может быть недостаточно.
4. Добавь клонированную папку как локальный проект в Codex и начни чат из этого проекта.
5. Попроси прочитать AGENTS.md, DEVELOPMENT-STATE.md, MANAGER-V2.md и последнюю заметку RELEASE,
   проверить ветку main и только потом продолжать твою задачу.

Готовая формулировка для домашнего чата:

> Продолжаем BARS Manager 3000 из https://github.com/forslaey/Bars-Manager-3000.
> Клонируй репозиторий, если локальной копии ещё нет. Если папка уже есть, сначала проверь git status,
> не стирай её изменения. Получи актуальный main. Прочитай AGENTS.md, DEVELOPMENT-STATE.md,
> MANAGER-V2.md, RELEASE-2.1.0.md и TEST-RESULTS.md. Затем кратко подтверди текущее состояние
> и жди моей новой задачи. Все сборки пока без подписи.

## При переключении между компьютерами

Заканчивая работу на одном компьютере, опубликуй коммит и обновлённый DEVELOPMENT-STATE.md.
Перед работой на другом — проверь git status и получи изменения через git pull --ff-only.
Если есть локальные изменения или ветки разошлись, сначала разберись с ними, не используй reset --hard и force push.

Уже настроенному домашнему чату достаточно: «Обнови main из GitHub, прочитай DEVELOPMENT-STATE.md и продолжай».
Само подключение репозитория не является автоматическим разрешением выполнять любые будущие установки
в Windows: реальные установщики и системные изменения требуют конкретной задачи пользователя.
