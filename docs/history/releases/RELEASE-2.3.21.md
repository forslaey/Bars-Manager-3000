# 2.3.21 — проверка и исправление DPI на рабочем компьютере

23.10.2026. Локальная сборка без цифровой подписи. На GitHub последним опубликованным остаётся 2.3.20.

После получения домашнего main 4d469f4 воспроизведены ошибки HeaderStyleTests и ResponsiveLayoutTests при настоящем Windows DPI 120 (125%). Изменения 2.3.20 сохранены, бизнес-логика установки, удаления, служб, ассоциаций и политик не менялась.

Исправлено в программе:
- Общие модули больше не масштабируют базовую шапку до завершения конструирования дочернего окна. Масштабирование из единиц 96 DPI выполняется один раз перед Load, повторное создание handle не масштабирует содержимое снова. Исходная область Root получает размер окна, чтобы промежуточная узкая ячейка не сжимала кнопки без последующего восстановления.
- Контейнер служб растягивает содержимое явно и показывает прокрутку при превышении минимальных размеров. Устранены неучтённый overflow Dock.Fill и залипшие полосы после смены размеров. Расчёт границ отложен до завершения текущего layout/scale, пересчитывается после изменения полос прокрутки.
- Подпись тумблера обновления служб занимает всю выделенную колонку: исключён преждевременный неточный расчёт ширины. Добавлена проверка полного текста тумблеров.
- Компактные лаунчер и утилиты сохраняют центрирование и размеры; их контейнер также не вмешивается в середину масштабирования дерева контролов.
- Первоначальный размер обычных окон ограничен рабочей областью монитора. Большое содержимое программ доступно прокруткой; проверена достижимость нижней кнопки «В меню». Нативные полосы соответствуют теме.

Исправлено в тестах:
- Сравнение одинаковой геометрии заголовков делается при одинаковой достаточной ширине окна: прежние 1080 пикселей на 125% были меньше реального минимума части модулей.
- ResponsiveLayoutTests нормализует реальный DPI перед имитацией 100/125/150/200%. Иначе 125% рабочего стола дополнительно умножались на коэффициент теста. Исходный и восстановленный размеры задаются одинаковым ClientSize, исключая разницу от ограничения размеров окна физическим монитором.
- LayoutFitTests учитывает фактический DPI в пиксельных ожиданиях отступов и размеров. Эти проверки выполнялись при реальных 125% и дополнительных коэффициентах геометрии 1/1.25/1.5/2; это не физическая смена DPI монитора.

Проверки: HeaderStyleTests 122 (74 нативных проверки темы строки заголовка, одинаковые заголовки, отсутствие повторного scale при RecreateHandle); ResponsiveLayoutTests 5224 (все модули, обе темы, горизонтальные/портретные размеры, повторное восстановление, стартовые размеры в рабочей области и достижимость нижних кнопок); LayoutFitTests 1676; NewSettingsTests 186; GuideDpiTests 626 при реальном DPI120; TouchGridTests 39; SoftwareConfirmationTests 27. Просмотрены изображения собранного EXE для служб, программ и лаунчера. Реальных установок, изменения настроек Windows и VM-тестов не проводилось. Физический КСО и перенос между мониторами с разным DPI в этом проходе не проверены.
