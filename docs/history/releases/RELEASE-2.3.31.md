# BARS Manager 3000 2.3.31 — сенсорный режим КСО

26.10.2026. Неподписанный выпуск. Пользователь поручил публикацию исходников и готовой программы на GitHub. [Релиз 2.3.31](https://github.com/forslaey/Bars-Manager-3000/releases/tag/v2.3.31).

В «Первичные системные настройки» добавлена строка «Сенсорный режим КСО» с действиями «Применить настройки КСО» и «Вернуть прежние настройки». Автопроверка читает состояние вместе с остальными настройками. Модифицируется только выбранная новая группа, существующие описания не переписаны.

## Область применения

Обе политики записываются в 64-битное представление HKLM на x64 Windows (в обычное на x86):
- SOFTWARE\Policies\Microsoft\Windows\EdgeUI: AllowEdgeSwipe, DWORD 0.
- SOFTWARE\Policies\Microsoft\Windows\Explorer: DisableNotificationCenter, DWORD 1.

Это область компьютера для всех пользователей; профиль повышенного администратора HKCU не используется. Изменения не зависят от имени пользователя, места запуска менеджера или флешки. Обычная прокрутка внутри программ не перенастраивается. Баннеры уведомлений, сочетания клавиш, оболочка и PosKiosk не модифицируются. Это ограничение двух способов вызова системного интерфейса, а не полный режим киоска.

Документированные редакции: Pro, Enterprise, Education, IoT Enterprise и их варианты. В Home и неизвестных клиентских редакциях запись разрешена с явным предупреждением: наличие значений не доказывает, что Windows исполняет политику. Неподтверждённые дополнительные ключи и обходы не добавлены. Для Windows Server новая функция отмечена как недоступная; существующие возможности менеджера не отключаются. Поддержка основного менеджера Server 2019+ с рабочим столом сохраняется.

Источники: [AllowEdgeSwipe](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-lockdown), [DisableNotificationCenter](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-taskbar). На компьютере разработки дополнительно проверено class="Both" в EdgeUI.admx и Taskbar.admx. Настройки реестра могут быть изменены доменными политиками/MDM; менеджер их не обходит.

## Восстановление и сбои

Перед первым изменением оба исходных значения сохраняются одной XML-копией в REG_BINARY: HKLM\SOFTWARE\BARS\Manager\KioskTouch, OriginalSettingsV1. Раздел защищён ACL для SYSTEM и администраторов. Сохраняются наличие, тип и данные, включая отсутствие значения; повторное применение копию не обновляет. Копия не переносится на флешке и относится только к этому компьютеру.

Запись копии проверяется до изменения политик; повреждённая копия блокирует изменение. Частичный сбой сохраняет возможность восстановления. Откат возвращает прежние значения или удаляет только два ранее отсутствовавших параметра; разделы целиком не удаляются. Если значения изменены внешним инструментом/политикой и не совпадают с ожидаемыми, восстановление останавливается без перезаписи. Копия удаляется после подтверждения восстановления. Параллельные изменения этой группы разными экземплярами менеджера сериализуются именованным mutex.

После изменения/восстановления возвращается 3010 и предлагается перезагрузка без автоматического запуска. Повторное применение без изменения значений не требует новой перезагрузки. Наличие записанных политик показывается отдельно от подтверждения реального поведения жестов. Для проверки результата нужно перезагрузить КСО и проверить краевые жесты под рабочим пользователем.

## Проверки

Целевые проверки используют поддельное хранилище реестра в памяти: типы данных, удаление ранее отсутствовавших значений, повторное применение, повреждённая/несохранённая копия, сбой второго изменения, повтор восстановления, внешние изменения, редакции и доступность кнопок. Интерфейс проверяется в обеих темах и с имитацией DPI/размеров. Реальные политики компьютера, установки, службы и перезагрузка не выполнялись. Испытания фактического подавления жестов на Home/Pro/Enterprise и физическом КСО остаются отдельным этапом.

Расширенный прежний Ui2330Tests при сборке с действующим DPI-манифестом не проходит старую проверку равенства отступов в менеджере служб (21/25 пикселей при 125%). Повторено на исходниках 2.3.30 с тем же манифестом: результат тот же. Старый сохранённый тест без этого манифеста проходит. Код служб и сам тест не изменены; полный Test.ps1 не объявляется успешно пройденным.

Итог целевого прогона: KioskTouchTests — 198, SystemSettingsRegressionTests — 100, LayoutFitTests — 1684, Core — 62, Management — 72, ManagedStore — 88. Шесть искусственных окон при дополнительном масштабе 200% поверх реальных 125% не вместили целую строку; проверки прокрутки в них явно пропущены и не считаются прошедшими. Фактические КСО и Home/Pro/Enterprise с перезагрузкой не испытывались. Снимки нового пункта просмотрены в обеих темах.
