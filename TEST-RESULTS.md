# Исправление .NET 11 RC — версия 2.0.4, 19.10.2026

В 2.0.3 полная версия каталога 11.0.0-rc.1.26425.128 сравнивалась напрямую с кратким названием MSI «11.0.0 RC 1». Из-за этого четыре установленных runtime имели статус «Нужна проверка» и счётчик составлял 34/40. Это ошибка сопоставления менеджера, а не свидетельство неудачной установки этих пакетов.

В 2.0.4 читаемые названия RC/Preview сопоставляются с каноническими версиями. Подтверждение предварительного runtime требует одновременно:
- наличия каталога точной полной версии и основного файла нужного семейства/разрядности;
- совпадения полной ProductVersion внутри System.Private.CoreLib.dll (для .NET Runtime) или Microsoft.AspNetCore.dll (для ASP.NET Core), с допустимым суффиксом +commit;
- действующей регистрации подходящей версии RC/Preview в Windows.

RC 1 не принимается за RC 10 или Preview 1, предварительная версия не заменяет стабильную, явно другой номер сборки не совпадает. Отсутствующие файлы/регистрация по-прежнему не дают «Установлено». Если найдено несколько неоднозначных записей одной предварительной версии, автоматическое удаление блокируется.

Проверка настоящих файлов и MSI этого компьютера без изменений системы: все четыре пакета .NET/ASP.NET Core 11.0.0-rc.1.26425.128 (x86/x64) подтверждены; снова 38/40. Диагностический отчёт system-check.txt сохранён рядом с копией программы в outputs/manager-v204. Пройдены 109 библиотечных, 46 UI и 62 проверки сопоставления/команд/процессов; добавлены 11 сценариев RC и защиты от ложного совпадения. Реальные установки/удаления не запускались. Сборка не подписана.

Профиль VC++ пока не изменён. По _About.txt и скриншоту выбран только набор 2005–2013 с тихой установкой, без RuntimePack Lite и без VC++ 2015–2022. Имена задач из присланных CMD относятся к v1522; точное имя задачи набора 2005–2013 в них отсутствует. Попытка извлечь сценарий EXE распаковщиком не удалась; это само по себе не доказывает повреждение установщика. Произвольный /TASKS не добавлялся. Требование v14 в старой проверке не соответствует выбранному профилю, но изменять профиль запуска без точного ключа нельзя.

# Исправления 2.0.3 — 19.10.2026

Ошибка запуска деинсталлятора воспроизведена до исправления на безопасном дочернем процессе: пустой ProcessStartInfo.WorkingDirectory передавался в CreateProcessW как пустая строка, что приводило к ERROR_INVALID_NAME / «Синтаксическая ошибка в имени файла, имени папки или метке тома». Теперь незаданная рабочая папка передаётся как NULL; MSI-деинсталлятор дополнительно получает существующую системную папку. После исправления тот же процесс запускается и завершается успешно. Это исправление запуска, а не подтверждение успешности всех сторонних установщиков.

Ошибки рабочего процесса теперь сохраняют исходный код Win32, путь EXE и рабочую папку. Полный текст исключения записывается в %PROGRAMDATA%\BARS\Manager\LibraryLogs\<сеанс>\<компонент>-error.txt; путь выводится в журнале. Активные процессы принудительно не завершаются.

.NET Runtime и ASP.NET Core проверяются по файлам конкретной версии/разрядности и действующей регистрации в Windows. Остатки DLL либо устаревшая запись без действующей регистрации MSI дают «Нужна проверка», а не «Установлено». Запись MSI без файлов также не считается полноценной установкой. Если осталась подходящая новая версия, она показывается вместе с её каталогом и названием регистрации. Сохранённый XML-каталог содержит требования к пакетам, а не кэш установленного состояния; каждая проверка заново читает систему.

У .NET Framework Developer Pack дополнительно проверена действующая регистрация SDK и Targeting Pack. У Access Database Engine наличие только COM/DLL без самостоятельной установки также считается неоднозначным состоянием. Предварительные .NET, чья полная версия не сопоставляется однозначно с записью Windows, теперь требуют проверки, даже если файлы есть. RuntimePack и обнаружение VC++ не менялись.

ASP.NET Core на текущем компьютере доступен в C:\Program Files\dotnet\shared\Microsoft.AspNetCore.App и C:\Program Files (x86)\dotnet\shared\Microsoft.AspNetCore.App. Проверено командами обоих dotnet.exe --list-runtimes. Его отдельные записи MSI имеют SystemComponent=1, поэтому не отображаются обычным списком установленных программ. В системе также доступны более новые runtime 8.0.32, 9.0.21 и 10.0.13; удаление старой версии не означает удаления этих новых версий.

Проверки: дефект пустой рабочей папки воспроизведён до изменения и устранён после него. Полный существующий набор прошёл после основного исправления; после усиления проверки файлов/регистрации повторены 109 библиотечных, 46 UI и 51 проверка запуска/удаления/сопоставления, включая семь сценариев остатков и повреждений runtime. Проверена текущая система в режиме чтения: 34 подтверждённых компонента, 5 неоднозначных (в том числе четыре предварительных .NET), 1 не найденный VC++. Отчёт system-check.txt лежит рядом с копией EXE в outputs/manager-v203.

Реальные установки и удаления библиотек этой сборкой НЕ выполнялись: их результат на чистой Windows пока не подтверждён. Нужна отдельная проверка в тестовой VM. Сборка без цифровой подписи, .NET Framework 4.6. Прежние исполняемые файлы и signed не заменены.
