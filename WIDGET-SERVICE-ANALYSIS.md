# Виджет 2.0.0: анализ установки службой

Изучен локальный комплект C:\DataKrat\Widget v2.0.0, 27.10.2026. Файлы комплекта не менялись, программа и её служба на рабочем компьютере не запускались.

- Точка запуска: **Bars.BackendWidget.exe**. Это отличается от старого примера Bars.WebStore.BackendWidget.exe.
- runtimeconfig требует Microsoft.NETCore.App и Microsoft.AspNetCore.App **10.0.0**. Версия установленного runtime и архитектура должны проверяться отдельно.
- deps содержит Microsoft.Extensions.Hosting.WindowsServices 9.0.2. Статический разбор IL Bars.BackendWidget.dll подтвердил вызовы **IsWindowsService и UseWindowsService**; это сильнее, чем простое наличие DLL в папке.
- Рабочая конфигурация расположена в **configs/appsettings.Production.json**; есть шаблоны в defaults/configs. В StaticFilesSettings оба поля IndexPath и PublicPath сейчас равны `.\widgets`.
- Для этого расположения корректные JSON-значения: `"IndexPath": "C:\\DataKrat\\Widget v2.0.0\\Widgets"` и аналогично PublicPath. В присланной старой инструкции тройная обратная косая черта перед widgets создаёт недопустимую JSON-последовательность `\w`.

## Рекомендуемый будущий режим

Явный профиль виджета: проверка файла/метаданных, runtime, папки Widgets и рабочего конфига; предварительный просмотр изменений, резервная копия, замена только двух нужных свойств с проверкой JSON; затем регистрация в SCM с системным именем Bars.BackendWidget, автоматическим запуском и корректно заключённым в кавычки полным путём. При удалении — остановка, ожидание состояния Stopped и удаление регистрации, без удаления пользовательских файлов. Для реализации предпочтителен Windows API SCM; при ручной работе используется sc.exe (не sc-алиас PowerShell).

Отсутствие obj= при sc.exe create означает LocalSystem. Учётную запись и права на файлы следует выбирать осознанно. Регистрация не означает успешный старт: нужен отдельный контроль Running и журнала приложения. Другие вызовы GetCurrentDirectory в сборке также требуют реальной проверки в изолированной VM.

**Не вводить слепой fallback после любой ошибки -i.** Такой установщик мог уже частично зарегистрировать службу или завершиться из-за настроек/прав. У произвольного EXE вообще может не быть поддержки протокола службы. Нужен известный профиль установки и проверка существующей регистрации/пути, а не догадка по коду возврата.

## Что не доказано

Реальная установка и запуск этой версии виджета, доступность его ресурсов под выбранной учётной записью и рабочие HTTP-сценарии не проверялись. В текущий выпуск менеджера новый способ установки/правка конфигов не включены: пользователь обозначил это как исследовательский вопрос.
